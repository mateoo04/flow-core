Yes, it’s possible to log prompts and tool/hook events, but that exact snippet is not valid as pasted.

A few issues:

Opis kolegija 1 makes the JSON invalid.
preToolUse is probably wrong casing; most hook systems use PreToolUse.
This logs the user prompt and tool-use payloads, not necessarily the assistant’s final answers.
The folder C:\git\.github\hooks must already exist, or Add-Content may fail.
Be careful: this can log secrets, API keys, private code, passwords pasted into prompts, etc.
A cleaned-up version would look like this:

{
  "hooks": {
    "UserPromptSubmit": [
      {
        "type": "command",
        "command": "powershell.exe -ExecutionPolicy Bypass -Command \"New-Item -ItemType Directory -Force -Path 'C:\\git\\.github\\hooks' | Out-Null; $input | Add-Content -Path 'C:\\git\\.github\\hooks\\agent_log.txt'\""
      }
    ],
    "PreToolUse": [
      {
        "type": "command",
        "command": "powershell.exe -ExecutionPolicy Bypass -Command \"New-Item -ItemType Directory -Force -Path 'C:\\git\\.github\\hooks' | Out-Null; $input | Add-Content -Path 'C:\\git\\.github\\hooks\\agent_log.txt'\""
      }
    ]
  }
}
Where to put it depends on the tool:

If this is Claude Code, it usually goes in a Claude settings JSON file, such as .claude/settings.json for a project or a user-level settings file.
If this is Codex, that exact JSON format likely will not apply directly; Codex uses config.toml style configuration, so the hook syntax would be different.
For logging “my answers,” a prompt hook alone is not enough. You would need either a supported “conversation/stop/post-response” hook, or use the tool’s built-in session logs/transcript if it provides one. So: logging prompts is straightforward; logging assistant answers depends on whether your specific agent tool exposes a response/transcript hook.
